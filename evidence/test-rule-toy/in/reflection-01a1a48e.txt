Decision reflection 01a1a48e (platform, mail auth): Mail auth is an adapter pattern behind the required login(user, password, address) port, with prebuilt strategies in separate MIT packages so core ships no credential store. Basic: a deployer-supplied list in a platform secret, PBKDF2 at 100,000 iterations because WebCrypto is what the edge offers, so passwords are generated and long, never chosen, because the hash cannot protect a weak one. KV: the same check against a small get port, Redis protocol first, Cloudflare KV as its own implementation since it does not speak Redis and is eventually consistent. better-auth: platform-kit's auth, for SSO, passkeys and app passwords; a mail app still sends an app password since IMAP has no SSO. Everything runs at the edge: no startup, no files, no in-memory counters, no connection pool, and contract tests run in workerd. Rate limiting, audit events and revocation wrap every strategy. Basic and KV need no SQL migrations, so they do not wait on the D1 schema path.
